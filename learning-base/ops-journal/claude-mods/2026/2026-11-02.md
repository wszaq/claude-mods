# 2026-11-02 claude-mods

## session-panel 0.3.4: the command is now `/session-panel`

The Mac did not show the Session pane. There were two causes.

1. The Mac clone was 11 commits behind `origin/main`, so it had no `session-panel` folder.
   The synced `settings.json` enabled `session-panel@claude-mods`, but the Mac marketplace did not have the plugin.
   We pulled the clone (fast-forward), installed `session-panel`, and updated `peer-radar` from 0.1.1 to 0.1.2.
2. Claude Code 2.1.316 (Mac) has a built-in `/session` command. `$.command.register` refuses the name of a built-in.
   The refusal stopped the `session.start` hook before `$.ui.open`, so the pane did not open and `/session` did nothing.
   The ThinkPad has 2.1.311, which does not have the built-in, so the pane worked there.

The mod now registers `/session-panel`. The pane ID stays `session`, so the saved card state does not change.
The README, the usage guide, the reference and the two wiki copies name the new command.

Verification: a new test stubs `command.register` to refuse `session`, as 2.1.316 does.
The test failed before the fix ("session.start hook was skipped") and passed after it.
`claude plugin validate session-panel` no longer reports the built-in name.
`claude plugin test` passed 60 of 60 tests: close-gate 10, waste-alarm 9, verify-gate 19, peer-radar 9, deliverable-dock 9, session-panel 4.

Lesson: an upgrade of Claude Code can add a built-in command with the same name as a mod command.
After an upgrade, run `claude plugin validate` on each mod and read the warnings, because a warning does not change the exit code.

## verify-gate 0.1.5: the command is now `/verify-gate`

A validate run on all ten installed mods found one more built-in name: Claude Code 2.1.316 also ships `/verify`.
verify-gate catches the refusal, so automatic checks still ran. But `/verify on|off|log` and the footer hint `/verify log` went to the built-in command, not to the mod.
The mod now registers `/verify-gate`. The code, the tests, the README, the usage guide, the troubleshooting page, the reference and the wiki copies use the new name.
The other eight mods (four claude-mods, four nateherk-mods) have no built-in name.

Verification: a new test records the registered name and refuses `verify`. It failed before the fix (`["verify"]`) and passed after it.
`claude plugin validate verify-gate` passed with no warning. `claude plugin test` passed 61 of 61 tests (verify-gate 20).

## The Session pane look for the other five mods

The operator chose these options: restyle each mod's own pane, change only the claude-mods (not the nateherk-mods), and change the panes and the bands.
A new file `hooks/look.tsx` holds the look of the Session pane: status glyphs in theme colors (✓ suggestion, ● claude, ○ inactive, ✗ error, ● warning) and a bordered card with a bold title.
A hooks module can import only files of its own plugin, so each of the five mods has an identical copy.

- peer-radar 0.1.3: the board has cards for this machine, the peer, Sync and Vault. Each card folds with its title, and the state stays across sessions (`collapsed` in the state contract and in `$.store`).
- waste-alarm 0.1.5: the pane has two folding cards, Tips and Today's repeated commands. The band starts with a yellow ●.
- deliverable-dock 0.1.5: the pane is one Deliverables card with plain buttons. The band starts with a ✓ instead of 📦.
- verify-gate 0.1.6: the band colors its ● running, ✓ pass and ✗ fail glyphs. The log pane is one "Last check" card.
- close-gate 0.1.5: the band starts with a yellow ●.

A pane with one card does not fold, because folding would hide the whole pane.
The glyph sits inside the label's Text, so each band label stays one Text and the old text tests still apply.
The reference and its wiki copy describe the folding cards.

Verification: each restyled render mounts on terminal and desktop in a test, and each test checks the glyph color.
The tests also check folding and the saved state for peer-radar, and folding for waste-alarm.
`claude plugin validate` passed for all six mods. `claude plugin test` passed 62 of 62 tests.
A color mutant in each copy of `look.tsx` failed the tests of that mod (1, 1, 1, 1 and 2 failures).

Lesson: `mock.store` returns nothing, and a second `on('store.set')` in the same test does not load. To read what a mod saved, answer `store.get` and `store.set` from a Map in the test.
In a test, `find({ key })` did not find a keyed Text inside a card body. Find the Text by its shown text.

## session-panel 0.3.5: `/session-panel` always shows the pane

In a new Desktop chat (bundled Claude Code 2.1.309) the operator did not see the Session pane.
The first `/session-panel` answered "Session pane closed.": the engine had placed the pane at session start, but the Desktop app did not show it. The second run opened it, and the operator then saw all five cards.
The command now closes the pane and opens it as asked, which is the order that showed it. `/session-panel close` closes it.
The reference, the usage guide and their wiki copies say this.

Verification: a new test answers `ui.panes` with a placed pane. It failed before the fix ("Session pane closed.") and passed after it.
`claude plugin test session-panel` passed 5 of 5 on 2.1.316 and on the Desktop's 2.1.309. Validation passed.
Not verified: that the close-then-open in one command shows the pane in the Desktop app. The operator's two separate runs did.

Lesson: the Desktop app runs its own Claude Code (`~/Library/Application Support/Claude/claude-code/<version>/`), not the terminal's.
Check a mod with that binary: `"<that path>/claude.app/Contents/MacOS/claude" plugin test <mod>`.
Live check: in a new Desktop chat with 0.3.5, one `/session-panel` showed the pane (operator, 2026-11-02).
