# Work journal — 2026-10-09

## Source of the mods

The five mods come from a work-profile study of the session logs on the Mac and the ThinkPad. The study used 3,246 unique typed prompts from 2026-07-01 to 2026-10-09. A Haiku 5.5 fan-out read the prompt shards, and one Sonnet 5.5 agent merged the results. The report is `docs/Projects/claude-workflow-mods/2026-10-09-work-profile-and-top5-mods.md` in the WAJBKODING workspace. The extractor and its 13-check eval are in `claude-work-profile/` in the workspace root repo.

## Build

Codex (gpt-6-sol, medium effort) built each mod from a written spec and brief. Claude wrote the briefs and reviewed and verified each result. The mods are function-hook plugins:

- **close-gate**: a band with uncommitted and unpushed changes, worktrees, dev ports and open items. It has the `running_state` tool, a hint for `session-handoff`, a facts block on close questions, and `/closeok`.
- **waste-alarm**: counts repeated Bash commands each day and runs the token-dashboard tips. It has `/waste`, a band and a pane.
- **verify-gate**: runs one repo check after a turn that edited files, and adds one note for a new failure. It has `/verify`.
- **peer-radar**: shows the state of the other machine over SSH, git fetch state and the vault sync. It has `/radar` and `/relay`.
- **deliverable-dock**: records output files and copies them to a delivery folder. It has `/ship` and a pane.

## Review fixes

Review found these problems, and Codex fixed them in later rounds:

- The verify-gate tests used `mock.session`, which the 2.1.292 test kit does not have. A test hook on `session.append` now records the notes, and it calls `next`.
- On 2.1.292 the engine has no `session.append`. The note is now in a try/catch, and the band still shows the failure.
- The AbovePrompt band is one instance. Each band mod now draws its line above the result of `next(e)`, so the mods do not hide each other.
- Headless runs (`claude -p` and the SDK) must stay quiet. The mods now skip timers, SSH, automatic checks and toasts when `isInteractive` is false.

## Install and backup

The mods are in the private repo `github.com/wszaq/claude-mods`. Each machine has a symlink `~/.claude/claude-mods` to its own clone. The folder marketplace path in the synced `settings.json` is `~/.claude/claude-mods`, because `claude plugin marketplace add` writes an absolute path that does not exist on the other machine. We upgraded the ThinkPad Claude Code from 2.1.292 to 2.1.293 with `mise`, so that `session.append` works there.

## Update of the installed copies

The installed mods are copies made at install time, and the plugin cache keys them on the version. After the integration round, both machines still ran the old 0.1.0 code. We bumped all five mods to 0.1.1 and ran `claude plugin marketplace update` and `claude plugin update` on both machines. Both machines now have 0.1.1 installed. The installed code has the three composed bands and the five headless guards. The `~` marketplace path did not change. The README now has the update steps.

A headless `claude -p` run ends before the mod timers start, so its debug log cannot show that the mods stay quiet. The unit tests are the evidence for headless quiet.
